# Automated Firmware Testing

## Description

У цій роботі реалізовано автоматизоване тестування firmware пристрою
за допомогою власного класу `DeviceDriver`.

Взаємодія з пристроєм виконується через UART.
COM-порт визначається динамічно за VID/PID без використання
захардкодженого імені порту.

Параметри UART-з'єднання: 115200 baud, 8N1.

## Implemented Tests

### Test 1 — Sensor History

Перевіряється кількість записів, які повертає команда `sensor history`
після накопичення більше 8 показань сенсора.

Очікуваний результат: 10 записів.

Фактичний результат: отримано 4 записи.

**Result: PASS — bug reproduced.**

### Test 2 — LED Blink

Перевіряється виконання команди `led blink 15`.

Очікуваний час виконання: приблизно 4.5 секунди
(15 × 300 мс).

Фактичний час виконання: приблизно 2.11 секунди.
Firmware виконує лише 10 blink замість 15.

**Result: PASS — bug reproduced.**

### Test 3 — Login Rate Limit

Виконується три послідовні спроби авторизації з неправильним паролем,
після чого виконується спроба входу з правильними обліковими даними.

Після трьох невдалих спроб firmware блокує обліковий запис,
і правильна авторизація не створює сесію.

**Result: PASS — bug reproduced.**

## Implementation Details

`DeviceDriver` реалізує:
- відкриття та безпечне закриття UART-з'єднання;
- відправлення команд із завершенням `\r\n`;
- читання відповідей пристрою;
- очищення отриманих рядків від ANSI escape-кодів;
- очікування заданого повідомлення з timeout;
- реєстрацію та авторизацію користувача.

У `test_bugs.py` реалізовано динамічний пошук UART-порту
та безпечне закриття з'єднання через конструкцію `try/finally`.

## Files

- `device_driver.py` — клас для взаємодії з пристроєм через UART.
- `test_bugs.py` — автоматизовані тести дефектів firmware.
- `test_results.png` — скріншот результатів виконання тестів.
