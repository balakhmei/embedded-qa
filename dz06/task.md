Домашнє завдання
Навчіться автоматизовувати перевірку знайдених дефектів за допомогою скриптів Python та бібліотеки pyserial. Результатом роботи мають бути функціональний модуль DeviceDriver та мінімум 2 автотести, що відтворюють баги з ваших попередніх звітів.

Матеріали та залежності

Джерело матеріалів: Використовуйте файли з папки fw_2 у GitHub-репозиторії.
Необхідна бібліотека:pip install pyserial
Частина 1. Пошук порту та базове підключення

Список портів: Напишіть скрипт, який знаходить та виводить у консоль усі доступні COM-порти на вашому ПК (підказка: serial.tools.list_ports.comports()).
Параметри підключення: Налаштуйте з'єднання з пристроєм вручну з наступними значеннями:
baudrate: 115200
bytesize: 8
parity: N (None)
stopbits: 1
timeout: 2
Перша команда: Надішліть команду help\r\n та виведіть необроблену (сиру) відповідь у термінал. Зверніть увагу на ANSI escape-коди, символи \r\n та префікси ESP_LOG.
Питання для роздумів (відповідь здавати не потрібно):

Чому readline() може зависнути під час роботи з embedded-пристроєм?
Що означає послідовність \r\033[K і навіщо прошивка її надсилає?
Частина 2. Реалізація класу DeviceDriver

Створіть файл device_driver.py із класом DeviceDriver, який повинен мати такі методи:

__init__(self, port, timeout=2) — конструктор, що зберігає параметри підключення.
open() — відкриває serial-з'єднання з параметрами 115200 8N1 та очищує вхідний буфер після відкриття.
close() — закриває поточне з'єднання.
send_command(command) — надсилає команду в порт (гарантує наявність \r\n у кінці), витримує паузу 0.1 секунди та повертає список рядків відповіді.
read_lines(timeout) — зчитує дані з порту протягом вказаного timeout, повертає список рядків (типу str, без \r\n), ігнорує порожні рядки та очищує текст від ANSI escape-кодів.
wait_for(pattern, timeout) — читає рядки до появи підрядка pattern. Повертає True, якщо рядок знайдено, або False, якщо вичерпано timeout.
login(login, password) — реєструє користувача (register), виконує авторизацію (login) та перевіряє наявність фрази "Session Started" у відповіді. Повертає True у разі успіху або False у разі помилки.
Підказки щодо реалізації:

serial.Serial(...) відкриває порт.
ser.readline() читає один рядок у вигляді байтів (bytes).
line.decode('utf-8', errors='replace') декодує байти у рядок (str).
re.sub(r'\x1b\[[0-9;]*[mK]', '', line) видаляє ANSI-коди.
time.time() зручно використовувати для розрахунку таймаутів.
Враховуйте, що пристрій може відповідати з невеликою затримкою.
Частина 3. Автоматизоване тестування

Використовуючи створений DeviceDriver, напишіть у файлі test_bugs.py тести для двох дефектів.

Обов'язковий тест (Тест 1): Некоректна кількість записів у sensor history
Підключитися до пристрою (через динамічний пошук порту).
Зареєструватися та авторизуватися (login).
Запустити збір даних: sensor start.
Витримати паузу (time.sleep), щоб накопичити понад 8 показань.
Зупинити збір: sensor stop.
Запросити історію: sensor history.
Порахувати кількість рядків із тегом [Sensor] у відповіді.
Перевірити умову: очікується 10 записів, але фактично отримуємо <= 5.
Вивести результат виконання: PASS або FAIL із поясненням.
Підказка для підрахунку: lines = [l for l in response if "[Sensor]" in l and "] temp:" in l]
Тест на вибір (виконайте один із трьох):
Варіант А (led blink обрізає значення > 10):
Надіслати команду led blink 15.
Заміряти час виконання за допомогою time.time().
Очікуваний час: ~4.5 сек (15 * 300 мс). Якщо тривалість менша за ~3.5 сек — баг підтверджено.
Варіант Б (rate limit блокує після 3 спроб):
Виконати login user wrongpass 3 рази поспіль.
Спробувати залогінитися з правильним паролем: login user correctpass.
Перевірити, що відповідь містить слово "locked", і переконатися у відсутності "Session Started".
Варіант В (config load без warning, якщо не було save): (Виконувати, якщо цей дефект було знайдено раніше)
Встановити параметр: config set alarm_threshold 50.
Завантажити конфігурацію без попереднього збереження: config load.
Запросити значення: config get alarm_threshold.
Переконатися, що значення скинулося на дефолтне (80), а в логах присутнє повідомлення "WARNING".

Критерії оцінювання

device_driver.py запускається та працює без помилок.
Метод send_command коректно форматує команди (додає \r\n).
Метод read_lines повертає очищені від ANSI-кодів рядки.
Метод wait_for правильно обробляє вихід за таймаутом.
Метод login() повертає True за умови коректних облікових даних.
Тест 1 та Тест 2 успішно виконуються та формують зрозумілий звіт (PASS/FAIL).
Код читабельний та містить коментарі у складних місцях.
Скрипт динамічно знаходить COM-порт замість захардкодженого значення.
Реалізовано безпечне закриття порту навіть у разі збою (використано try/finally або контекстний менеджер).
Типові проблеми та їх розв'язання

Помилка "Access is denied": Порт зайнятий іншою програмою (наприклад, monitor.bat або іншим терміналом). Закрийте їх перед запуском скрипту.
Порожня відповідь після команди: Збільште таймаут або додайте паузу time.sleep(0.5) одразу після send_command.
Зчитування застарілих даних: Викликайте ser.reset_input_buffer() одразу після відкриття serial-порту.
Логи у форматі I (1234) DEVICE: [Sensor] ...: Це стандартний формат ESP_LOG. Для витягнення чистого тексту використовуйте регулярний вираз: re.match(r'^([IWED]) \(\d+\) ([^:]+): (.+)$', line)
